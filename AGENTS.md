# AGENTS.md

Контракт для ИИ-агентов и новых разработчиков. Подробная карта проекта —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что это за проект

Браузерная игра на ванильном JS **без сборщика**. Обычные `<script src>` в `index.html`,
деплой на GitHub Pages простым копированием файлов. Нет npm-зависимостей в рантайме,
нет транспиляции, нет ES-модулей. Файлы в `tools/` — `.mjs` для Node, они в игру не попадают.

Из этого следует всё остальное: браузер грузит десятки мелких скриптов строго по порядку,
и они общаются через общую глобальную область видимости.

## Перед каждым коммитом

```bash
node tools/sync-sw-precache.mjs   # если трогал index.html или assets/
node tools/check-integrity.mjs
node tools/smoke.mjs
```

Всё запускается из корня репозитория. `smoke.mjs` требует jsdom — ставится разово
во временную папку: `npm install jsdom --prefix %TEMP%\consultant-smoke`.

## Правила, нарушение которых ломает сборку

1. **Новый `.js`-файл — новый `<script src>` в `index.html`**, в свой ярус (см. ниже).
   Забыл строку — код просто не выполнится, и ошибки не будет.
2. **Новый `.css`-файл — новый `<link>` в `<head>`.** Порядок: токены, база, UI-кит,
   виджеты, и последним `body-state.css`.
3. **Верхнеуровневые `const`/`class`/`function` — общие глобальные имена.** Два файла
   с одинаковым именем на верхнем уровне дают `SyntaxError` в браузере.
   `check-integrity.mjs` ловит это статически — не игнорируй его вывод.
4. **Не пиши `window.X = X`.** Верхнеуровневые объявления и так видны всем скриптам
   по имени. Такие экспорты уже вычищены, не возвращай их.
5. **Оборачивай файл в IIFE только если внутри нужен ранний `return`** (единственный
   пример — `src/game/modes/sale/dev-panel.js`). Обычный файл — плоский, с `'use strict';`
   первой строкой после шапки-комментария.
6. **Список прекеша в `sw.js` генерируется.** Правь его только через
   `node tools/sync-sw-precache.mjs`, руками блок между `const CACHE` и `// <<< generated`
   не трогай.
7. **`reference/` — чужой проект для сверки.** В сборку не попадает, не редактируй.

## Порядок подключения скриптов

Ярусы размечены комментариями в `index.html`. Внутри яруса порядок обычно свободный,
между ярусами — строгий.

| Ярус | Что | Почему здесь |
|---|---|---|
| 1 | `src/shared/lib/` | утилиты нужны всем |
| 2 | `src/game/data/` | таблицы читаются на старте |
| 3–5 | `render/`, `audio/`, `arena/`, `entities/` | классы сущностей до `Game` |
| 6 | `src/game/core/game.js` | объявляет `class Game` |
| 7 | остальные `core/`, `arena/`, `fx/`, `render/` | дописывают `Game.prototype` |
| 8 | `src/game/modes/sale/`, затем `gear/` | сначала `data/`, потом логика |
| 9 | `src/shared/ui/`, `src/widgets/` | виджеты и их `bindings` |
| 10 | `mount-widgets.js`, `bootstrap.js` | сборка разметки и `new Game()` |

Правило: **всё, что дописывает `Game.prototype`, идёт после яруса 6.** Всё, что читает
таблицу на этапе загрузки, — после её объявления.

## Куда класть код

| Добавляешь | Файл |
|---|---|
| Число баланса, таблицу | `src/game/data/*` или `src/game/modes/<режим>/data/*` |
| Метод забега «Распродажа» | подходящий по смыслу `src/game/modes/sale/<зона>.js` |
| Новое оружие | описание в `modes/sale/data/weapons.js` + логика в `modes/sale/weapons.js` |
| Нового босса | описание в `modes/sale/data/bosses.js` + поведение в `boss-ai.js` |
| Поведение врага | `src/game/entities/enemy.js` |
| Новый экран или попап | новая папка `src/widgets/<имя>/` |
| Переиспользуемый элемент UI | `src/shared/ui/<имя>/` |
| Утилиту без знания об игре | `src/shared/lib/` |
| Общий цвет, отступ, шрифт | `src/shared/styles/tokens.css` |

Если файл перевалил за ~400 строк или в нём появились две несвязанные зоны
ответственности — режь на файлы, это и был смысл текущей структуры.

## Три паттерна кода

**Таблица данных** — плоский файл, только константы:

```js
/**
 * Распродажа: Пулы минутных событий по фазам забега.
 */
'use strict';

const SALE_EVENT_POOLS = {
  early: ['queue_rush', 'happy_hour'],
  late: ['triple_boss', 'vip_day'],
};
```

**Методы `Game`** — дописываются в прототип, файл на одну зону:

```js
/** Распродажа: Спавн рядовых врагов. */
'use strict';

Game.prototype.spawnSaleEnemy = function (forcedType) { /* ... */ };
```

Для группы мелких методов — `Object.assign(Game.prototype, { ... })`.

**Виджет** — три файла в своей папке:

- `<виджет>.js` — глобальный объект с `mount(root)`, разметка в шаблонной строке,
  про `Game` не знает;
- `<виджет>.bindings.js` — `Object.assign(Game.prototype, {...})`, связка с игрой;
- `<виджет>.css` — стили с собственным префиксом классов.

Плюс пустой корень `<div id="...">` в `index.html` и строка в `src/app/mount-widgets.js`.
`mount()` вызывается до `new Game()`, потому что конструктор кэширует DOM-узлы.

## Стиль

- Имена файлов — `kebab-case.js`, шапка-комментарий с зоной ответственности.
- Комментарии и тексты в UI — по-русски.
- Комментарий объясняет ограничение или причину, а не пересказывает соседнюю строку.
- Отступ 2 пробела, одинарные кавычки, точка с запятой.
